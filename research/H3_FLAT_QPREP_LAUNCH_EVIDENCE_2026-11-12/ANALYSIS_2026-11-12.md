# Real HyperFlow H3 Flat GPU video tests — evidence review

Date: 2026-11-12. Scope: the raw evidence bundle committed at
`experiment/flat-qprep-profile-20261112@100628b1604d485bf9eafb2e5b2a3bd8343a1a11`.
This is a report review, NOT a new GPU measurement, runtime repair,
source-code validation, or production promotion.

## What was actually executed

Two **completed, output-producing** real ComfyUI video runs, using
`htrc_flat_gpu`, not a parallel shadow or a CPU synthetic QKV oracle.
Both used the same underlying MiniMax H3 HyperFlow Flash 14B NVFP4
checkpoint, seed 730251, image/reference/prompt, 1280x736 video
generation cropped to 1280x720, 56 frames at 24 fps, Euler with
HyperFlowSigmas and six denoising steps on RTX 5070 Ti 16 GiB.

The event logs explicitly report
`attention_profile=htrc_flat_gpu`,
`effective_mode=htrc_flat_gpu_actual_output` and
`heads=56, distinct_native_head_ids=true`. The native output branch
is active. Both end with `execution_success`; no CUDA OOM/guard abort.
This proves the selected Flat output path executed within a real
multi-step video workload. It does **not** prove adequate visual
quality or faster inference than accepted earlier Flat/Dense/Sol.

## Actual warm-call GPU attention profile (Q=0.3, call 2)

Real H3 attention had 18,723 tokens, 56 distinct heads, 19 query
windows, head-group capacity 13 (5 groups), and output 255.979 MiB.
Reported call wall: **169.0775 ms**.

Measured `profile_gpu_stream_elapsed_ms` (GPU event intervals,
including possible stream gaps):

- `query_stats_selection`: **112.1685 ms** (~66.34% of call wall).
- `tile`: 17.2147 ms.
- `merge_tail`: 2.9532 ms.
- `kv_workspace_setup`: 9.3364 ms.
- `output_copy`: 1.2340 ms.

CPU enqueue intervals differ (query_stats_selection 85.3387 ms;
Tile 17.5189 ms). Event intervals can overlap CPU scheduling and
include idle gaps. Never sum stage intervals as additive kernel-only
runtime. The first attention call took ~11.01 seconds and included
compile/startup artifacts; call 2 is the better profiling indicator.

**Decision from profile:** do not further prioritize Tile/Merge.
Focus on Q layout/gather/FP32 cast/MU, leaf statistics and especially
rowmax/topk/selection, plus per-window Python/Triton launch traffic.
Separate each substage in a synchronized diagnostic only, then
measure improvement in ordinary unsynchronized full video calls.

## Synthetic shape-matched preparation profile: secondary evidence

`H3_FLAT_QPREP_SHAPE_PROFILE_2026-11-12.json` used ZERO-valued
synthetic tensors, 18,723 tokens, 56 heads, 19 windows, 6 groups,
114 `prepare_batched_head_states` calls. The measured stage
medians per window/group were:

- Q gather, FP32 cast and MU: 0.338 ms.
- KV-cache validation: 0.030 ms.
- Leaf statistics: 0.396 ms.
- Rowmax/topk/exclusion: 0.368 ms.
- Sum of separate medians: 1.132 ms, or ~129 ms at 114 calls.

This is NOT an actual 129-ms model-attention timing. It excludes
Tile/Merge, true QKV values, model weights/residency, and startup
effects. Six K/V group-cache builds totalled 1026.761 ms, but
their median was only ~0.406 ms (p95 ~1020.667 ms): a cold-start
outlier dominates. The file does not isolate whether JIT,
allocations or other startup work caused that outlier.
Do not use these synthetic data to make video quality decisions.
